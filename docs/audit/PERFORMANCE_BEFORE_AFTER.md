## 2. ตัวเลขที่เทียบได้ — น้ำหนักสคริปต์

`njchat.js` มีขนาด **101 KB** และถูกโหลดใน **20 หน้า** ตั้งแต่วินาทีแรกเสมอ
ทั้งที่ผู้ใช้ส่วนใหญ่ไม่ได้เปิดแชทเลย

| | ก่อน | หลัง |
|---|---|---|
| ไฟล์แชทที่โหลดทันที | `njchat.js` **101 KB** | `njchatload.js` **4.5 KB** |
| หน้าที่ได้ผล | — | **19 หน้า** (ทุกหน้ายกเว้น `chat.html`) |
| **ลดลงต่อหน้า** | | **−96.5 KB** |
| JS ที่โหลดจริงบนหน้าแรก (ไม่บีบอัด) | ~256 KB | **155 KB** |

**แชทถูกโหลดเมื่อเกิดข้อใดข้อหนึ่ง** — ผ่านไป 18 วินาที · ผู้ใช้เลื่อนจอลง 400 px ·
ผู้ใช้แตะหรือกดปุ่มอะไรก็ได้ · กดลิงก์ "แชทกับน้อง" (โหลดแล้วเปิดให้ทันที)

**วัดจริงในเบราว์เซอร์ที่ 375 px:**
- เปิดหน้าแรก → `njchat.js` **ไม่ถูกโหลด** · มีแต่ตัวโหลด 4.5 KB ✅
- แตะจอหนึ่งครั้ง → `njchat.js` โหลด · ปุ่มแชทโผล่ทันที (ไม่หน่วงซ้ำ) · แผงยังไม่เปิดเอง ✅

## 3. หน้าแปลง — สิ่งที่บอตได้รับ

นี่คือการเปลี่ยนแปลงที่สำคัญที่สุดของรอบนี้ และวัดเป็นไบต์ไม่ได้

| | ก่อน | หลัง |
|---|---|---|
| HTML ที่บอตได้รับ | โครงหน้าเปล่า ไม่มีเนื้อหาแปลงเลย | ชื่อแปลง · ราคา · ที่ตั้ง · เนื้อที่ · รหัสทรัพย์ · รูป |
| `<title>` | เหมือนกันทุกแปลง | **22 แปลง 22 ชื่อ ไม่ซ้ำกันสักคู่** |
| `og:image` | ภาพกลางของเว็บทุกแปลง | **รูปของแปลงนั้นจริง** |
| Structured Data | ไม่มีใน HTML ต้นทาง | RealEstateListing + BreadcrumbList |
| อยู่ใน sitemap | **ไม่อยู่เลย** | `sitemaps/properties.xml` 22 URL |

**วัดจริง** หน้า `p/OP-072.html` ที่ 375 px: `domContentLoaded` **89 ms** ·
`<h1>` อยู่ใน HTML ต้นทางตั้งแต่ไบต์แรก · JS ต่อยอดขึ้นเป็นหน้าเต็ม (แกลเลอรี · แผนที่ ·
เครื่องคำนวณ · ปุ่มบันทึก) ได้ครบเหมือนเดิม

## 4. ⛔ สิ่งที่ยังแก้ไม่ได้ในรอบนี้ และเหตุผล

### 4.1 รูปประกาศยังเป็นไฟล์ต้นฉบับ (ประเด็นที่หนักที่สุดที่เหลืออยู่)

| | ค่า |
|---|---|
| ขนาดไฟล์จริง | **458 KB** ต่อใบ (1800 × 1013) |
| ช่องที่แสดงบนมือถือ | **390 × 160** |
| หน้าแรก 6 ใบ | ~2.7 MB |
| หน้ารวมประกาศ 22 ใบ | **~10 MB** |

⚠️ **แก้ที่ฝั่งเว็บไม่ได้** — รูปถูกเสิร์ฟจาก `app.njteedinsure.com/uploads/` ตรงๆ
ไม่มีชั้นแปลงขนาดอยู่ระหว่างทาง · ทางแก้จริงมีสองทาง ซึ่ง**ต้องให้เจ้าของเลือก**:

1. **ย่อตอนอัปโหลด** (ฝั่ง `nj-survey-system`) — สร้างไฟล์ขนาด 400/800/1600 px เก็บไว้
   แล้วส่ง `srcset` ออกมาทาง API · ได้ผลถาวร แต่รูปเก่า 22 แปลงต้องย่อย้อนหลัง
2. **ใส่ชั้นแปลงรูปหน้า Render** — เพิ่มเส้นทาง `/img/<w>/<ไฟล์>` ที่ย่อให้ตอนเรียก
   · ทำครั้งเดียวได้ผลกับรูปเก่าด้วย แต่กิน CPU ของเซิร์ฟเวอร์

ผู้ใช้บนเน็ตมือถือที่เลื่อนดูหน้ารวมประกาศจนจบ **ดาวน์โหลดประมาณ 10 MB** ทุกวันนี้

### 4.2 สคริปต์หน้าแปลงยังมี 18 ไฟล์

`land.html` โหลด 18 สคริปต์ (~193 KB ไม่บีบอัด) เพราะแต่ละแผงเป็นไฟล์ของตัวเอง
· ลดได้ด้วยการรวมไฟล์ตอน build แต่จะทำให้ **อ่าน diff ตอนรีวิวยากขึ้นมาก** และ
โปรเจกต์นี้ยังไม่มีตัวรวมไฟล์เลย — เป็นการแลกที่ควรตัดสินใจแยก ไม่ควรแถมมาในสปรินต์นี้

### 4.3 ไม่มี CDN และไม่ได้ตั้งค่าแคชเอง

GitHub Pages มี CDN และตั้ง `Cache-Control` ให้เองอยู่แล้ว (แก้ไม่ได้จากฝั่งเรา)
ส่วนรูปจาก `app.njteedinsure.com` วิ่งผ่าน Cloudflare อยู่แล้ว

## 5. สิ่งที่ยังไม่ได้วัดและควรวัดหลัง deploy

- Core Web Vitals จริง (LCP · INP · CLS) จาก PageSpeed Insights บน production
- ผลของการบีบอัด gzip/brotli ซึ่งเซิร์ฟเวอร์ทดสอบบนเครื่องไม่มี
- เวลาโหลดจริงบนเน็ตมือถือไทย (3G/4G)

⚠️ **ตัวเลขในเอกสารนี้ไม่ใช่ Core Web Vitals** อย่านำไปอ้างว่าเป็นคะแนน PageSpeed
