## 2. สิ่งที่ผ่าน

- **ไม่มี horizontal scroll ที่ความกว้างใดเลย** ทั้ง 10 ขนาด
- Layout ไม่แตกที่ขนาดใด · การ์ดจัดเรียง 1 / 2 / 3 คอลัมน์ตามความกว้างอย่างสมเหตุสมผล
- ภาพ hero มี `<picture>` สลับไฟล์แนวตั้งที่ต่ำกว่า 640 px (`photos/hero-mobile.jpg`) จึงไม่เห็นแต่แถบกลางแคบ ๆ บนมือถือ
- รองรับ `prefers-reduced-motion` ในทั้ง 3 ชุดสไตล์ (พบกฎ 3–5 จุดต่อหน้า)
- ที่ 1440 และ 1920 px เนื้อหาไม่ยืดเต็มจอ (มี `max-width: 1280px`) อ่านง่าย

## 3. ปัญหาที่พบ

### 3.1 High — เมนูเดสก์ท็อปหายตั้งแต่จอต่ำกว่า 1280 px

| จอที่ได้รับผล | ตัวอย่างอุปกรณ์ |
|---|---|
| 768 px | iPad แนวตั้ง |
| 1024 px | iPad Pro แนวตั้ง / iPad แนวนอน |
| 1152–1279 px | MacBook Air 11" · โน้ตบุ๊ก 1280×800 ที่ตั้ง zoom |

ที่ความกว้างเหล่านี้ผู้ใช้เห็นแค่ปุ่มแฮมเบอร์เกอร์ ทั้งที่จอกว้างพอจะแสดงเมนูเต็มได้สบาย

**สาเหตุ:** ทั้งสามชุดสไตล์ซ่อนเมนูที่จุดตัดคนละค่า (`home.css` ที่ 1040 px · `marketplace.css` ที่ 900 px · `ui.css` อีกค่า) และหน้าแรกซ่อนจริงที่ 1280 px เพราะแถวเมนูยาวเกินจะพอดี (CLAUDE.md บันทึกไว้เองว่าแถวนี้ "เต็มพอดี" ที่จอ 1440)

**ข้อเสนอ:** ลดจำนวนเมนูแถวแรกเหลือ 6 กลุ่มตามงานที่ 2 แล้วจึงตั้ง breakpoint เดียวกันทั้งเว็บที่ 1024 px

## 4. สิ่งที่ยังไม่ได้ทดสอบ

ทดสอบครั้งนี้ใช้การจำลองความกว้าง viewport ในเบราว์เซอร์เดียว (Chromium) ยังไม่ได้ทดสอบ

| รายการ | เหตุผล |
|---|---|
| Safari (macOS) · Mobile Safari (iOS) | ต้องใช้เครื่องจริงหรือ BrowserStack |
| Edge | ควรทดสอบก่อน production (คาดว่าเหมือน Chromium) |
| Mobile Chrome บนเครื่องจริง | การจำลอง viewport ไม่ครอบคลุม address bar ที่ยืดหดและ `100vh` |
| Safe area บน iPhone ที่มีรอยบาก | แถบเมนูล่างอาจชน home indicator |
| การหมุนจอแนวนอนบนมือถือ | — |

**ข้อเสนอ:** ทดสอบสามข้อแรกใน Sprint 6 ตามลำดับที่โจทย์กำหนด
