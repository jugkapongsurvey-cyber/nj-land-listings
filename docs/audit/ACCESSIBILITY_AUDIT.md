## 3. ปัญหาเรียงตามระดับ

### High

#### A11Y-01 — ไม่มี Skip Link ในหน้าใดเลย

ทุกหน้ามีเมนูหัวเว็บ 8–12 ลิงก์ · หน้าแรกมีลิงก์ + ปุ่มรวม **178 ชิ้น**
ผู้ใช้คีย์บอร์ดและโปรแกรมอ่านหน้าจอต้องกด Tab ผ่านเมนูทั้งชุดทุกครั้งที่เปลี่ยนหน้า

**แก้:** เพิ่ม `<a class="skip" href="#main">ข้ามไปเนื้อหาหลัก</a>` เป็นอิลิเมนต์แรกใน `<body>` และเพิ่ม `<main id="main">` ในหน้าที่ยังไม่มี

---

#### A11Y-02 — ช่องกรอก 7 ช่องไม่มี label ผูก

| หน้า | ช่อง | สิ่งที่ผู้ใช้ได้ยินตอนนี้ |
|---|---|---|
| `wanted.html` | `areaMin` `areaMax` `budgetMin` `budgetMax` | "แก้ไขข้อความ" เฉย ๆ ไม่รู้ว่าเป็นขั้นต่ำหรือขั้นสูง |
| `index.html` | ช่อง `text` 2 ช่อง (อยู่ในเครื่องคำนวณ) | เหมือนกัน |
| `land.html` | ช่อง `text` 1 ช่อง | เหมือนกัน |

กรณี `wanted.html` ร้ายแรงที่สุดเพราะเป็นคู่ "ตั้งแต่–ถึง" ที่แยกไม่ออกเลยถ้าไม่เห็นหน้าจอ

**แก้:** ใส่ `aria-label` ที่บอกทั้งชื่อช่องและบทบาท เช่น `aria-label="เนื้อที่ขั้นต่ำ (ตารางวา)"` หรือใช้ `<fieldset>` + `<legend>` ครอบคู่ช่วงค่า

---

#### A11Y-03 — ปุ่มและลิงก์เล็กกว่า 44 × 44 px จำนวน 73 ชิ้น

วัดบนหน้าแรกที่ 375 × 812 px — **73 จาก 178 ชิ้น (41%)** สูงไม่ถึง 44 px

จุดที่กระทบมากที่สุด

| จุด | ปัญหา |
|---|---|
| ไอคอนติดต่อในการ์ดประกาศ | เป็นตัวอักษรเดี่ยว (`●` `f` `☎` `📱`) ขนาดเล็กมาก อยู่ติดกัน 4 ปุ่ม — กดพลาดข้ามปุ่มได้ง่าย และเป็นปุ่มที่เปลี่ยนเป็นลีดโดยตรง |
| ลิงก์ในฟุตเตอร์ | 15 px เรียงชิด |
| ลิงก์ย่อยในการ์ดบริการ | — |

### Medium

#### A11Y-04 — ความต่างสีของป้าย "ข้อมูลเบื้องต้น" ไม่ผ่าน

| องค์ประกอบ | สี | พื้นหลัง | อัตราส่วน | ต้องการ | ผล |
|---|---|---|---|---|---|
| `.land-card .basic` ("◐ ข้อมูลเบื้องต้น") 12 px | `rgb(216,185,107)` | `rgb(107,87,30)` | **3.68 : 1** | 4.5 : 1 | **ตก** |

เป็นป้ายที่บอกระดับความน่าเชื่อถือของประกาศ ซึ่งเป็นจุดขายหลักของเว็บ — ตัวเล็ก (12 px) และอ่านยากที่สุดในหน้า

**ส่วนที่ผ่านทั้งหมด** (ตรวจ 13 จุด)

| องค์ประกอบ | อัตราส่วน |
|---|---|
| H1 ขาวบนน้ำเงิน | 16.52 : 1 |
| ตัวเลข Trust ทองบนน้ำเงิน | 8.71 : 1 |
| เนื้อหาเทาบนพื้นอ่อน | 5.09 : 1 |
| ลิงก์ฟุตเตอร์ | 5.58 : 1 |
| ข้อมูลย่อยในการ์ด | 9.00 : 1 |
| เมนูหัวเว็บ | 16.52 : 1 |

> ข้อควรระวัง: ตัวเลขของ H1 และเมนูหัวเว็บคำนวณจากสีพื้นหลัง CSS แต่จริง ๆ ข้อความทั้งสองลอยอยู่บน **ภาพถ่าย** ที่มีม่านไล่สีทับ อัตราส่วนจริงจึงเปลี่ยนไปตามภาพ ควรตรวจซ้ำด้วยภาพจริงตอนปรับ hero ใน Sprint 2

---

#### A11Y-05 — `alt` ของรูปการ์ดประกาศยาวเกินไป

ตัวอย่างจริงจาก production

> "แขวงคลองขวาง เขตภาษีเจริญ กรุงเทพมหานคร 10160 · 98200 - ขายบ้านเดี่ยวแปลงมุม 95.2 ตร.ว. หมู่บ้านนิศาชล บางแวก 79 · 0-0-95.2 ไร่"

ข้อความนี้ถูกอ่านซ้ำทันทีกับหัวข้อและรายละเอียดที่อยู่ถัดไปในการ์ดเดียวกัน · โปรแกรมอ่านหน้าจอจึงได้ยินข้อมูลเดิมสองรอบต่อการ์ดหนึ่งใบ คูณ 22 ใบในหน้ารวมประกาศ

**แก้:** ย่อเหลือสิ่งที่ *ภาพ* แสดงจริง เช่น "ภาพแปลงที่ดิน ต.ในคลองบางปลากด" หรือใส่ `alt=""` ถ้าหัวข้อการ์ดบอกครบแล้ว

---

#### A11Y-06 — หัวข้อข้ามลำดับใน `listings.html`

พบ 1 จุดที่ข้ามจาก H2 ไป H4 (หรือ H1 ไป H3) — ต้องไล่ดูตำแหน่งจริงตอนแก้

---

#### A11Y-07 — ไม่มี `<main>` ใน 9 หน้า

ทำให้คำสั่ง "ข้ามไปเนื้อหาหลัก" ของโปรแกรมอ่านหน้าจอใช้ไม่ได้ และเกี่ยวโยงกับ A11Y-01 โดยตรง

---

## 4. สิ่งที่ทำได้ดีอยู่แล้ว

| ข้อ | หลักฐาน |
|---|---|
| **H1 หนึ่งรายการต่อหน้าทุกหน้า** | 21/21 (ยกเว้น `land.html` ที่ต้องรอ JS) |
| **ไม่มีรูปที่ขาด `alt`** | 0 จากรูปรวม 85 รูปใน 7 หน้าที่ตรวจ DOM จริง |
| **ไม่มีลิงก์เปล่าที่ไม่มีชื่อ** | 0 |
| **มี `aria-live`** | 1–3 จุดต่อหน้า ครอบคลุมผลการค้นหาและข้อความผิดพลาด |
| **มีกฎ `:focus` / `:focus-visible`** | 13–18 กฎต่อหน้า ในทั้งสามชุดสไตล์ |
| **รองรับ `prefers-reduced-motion`** | 3–5 media query ต่อหน้า |
| **ปุ่มเปรียบเทียบใช้ `aria-pressed`** | `.njcmp-btn` |
| **แถบระดับตรวจสอบมี `role="img"` + `aria-label`** | "ผ่านการตรวจสอบ n จาก 5 ระดับ" ใน `verified.js` |
| **วิดีโอมี `aria-label` บอกเนื้อหาและความยาว** | `njintro.js` |
| **วิดีโอไม่เล่นเอง** และ HTML มี `controls` ตั้งแต่ต้น (JS เป็นคนถอด) | เมื่อ JS พัง ผู้ใช้ยังกดเล่นได้ |
| **`lang="th"` ทุกหน้า** | 21/21 |
| **`viewport` ไม่ล็อก zoom** | ไม่พบ `user-scalable=no` |
